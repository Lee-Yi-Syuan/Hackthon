API 介接與自動審核

哪些欄位機器自己判得掉、哪些要串外部系統、哪些非人看不可。這一頁是給承辦單位資訊科與評審看的。

六組裡，兩組已經處理掉了

匯率改接 open.er-api.com——免金鑰、有 CORS，前端可直連，現在就在運作。行政區乾脆不用 API：22 縣市 368 個鄉鎮市區直接內建，零延遲、離線可用，比呼叫外部服務可靠。

剩下四組本質上不可能從前端連：發票查驗的 appID 與 LINE 的 channel_secret 屬於機密，一放進前端就等於公開；戶政與社會救助則限機關以 T-Road 申請，不對外開放。這四組必須由市府端的後端實作。

在這個分享連結上，連匯率也會被擋

本頁若以沙箱化的網頁環境開啟，內容安全政策會封鎖所有對外請求，匯率會連線失敗並自動退回內建示意值——這是預期行為，不是壞掉。自行架站後即可實際連通。按上面的「實際試連」可以當場看到是哪一種情況。

#審核項目判定方式依據
為什麼這樣切分

格式、範圍、一致性這類判斷不需要人。把它們擋在送出之前，申請人當場就能改，不必等三天收到退件通知再重來一次——退件率下降，行政量能才有餘裕去辦工作坊。

真正需要人的只剩一件事：這個工具的用途，跟他寫的計畫是否相稱。那才是承辦人員該花時間的地方。

上線所需的後端代理

臺銀匯率與國土測繪中心行政區皆無 CORS 標頭，發票與戶政介接則涉及機密金鑰，四者都需要一層自家後端。實作上是四條路徑：/api/bot-rates、/api/districts、/api/einvoice/verify、/api/household/verify，各自轉發並快取即可。
